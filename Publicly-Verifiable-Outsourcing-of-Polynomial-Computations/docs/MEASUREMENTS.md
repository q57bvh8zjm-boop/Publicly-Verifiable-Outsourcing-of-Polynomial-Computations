# Measurement contract

`benchmarks/benchmark.c` performs actual query generation, all server evaluations, public verification, and reconstruction. It compares the final output with native polynomial evaluation before emitting a CSV row. The VAR case additionally checks direct matrix-vector multiplication for `sum_i (A*x)_i^2`, where `A_ij=1+((i+1)*(j+1) mod 7)`.

| Column | Meaning |
|---|---|
| `keygen_ms` | Fresh HSS setup once per invocation; repeated in rows for that key. Zero for Gamma1/2, whose query-specific work is in ProbGen. |
| `native_ms` | Mean of 100 native calls on the same public input; includes the evaluator's allocation and cleanup. |
| `probgen_ms` | Query generation, including fresh masks/encryptions and public verification key. |
| `server_total_ms` | Sum of local server computations executed sequentially on this machine. |
| `verify_ms` | Public verification and preparation of the decoding value. |
| `decode_ms` | Client reconstruction. Very short operations can round to the clock resolution. |
| `client_ms` | `probgen_ms + verify_ms + decode_ms`. |
| `client_ratio` | `client_ms / native_ms`, excluding setup and server work. |
| `input_bytes_per_server` | Canonical fixed-width payload estimate from actual parameters; excludes framing, setup keys, and distribution of the public verification key. |
| `response_bytes_per_server` | 64 bytes for Gamma1, `32*(d+1)` for Gamma2/3. |
| `paillier_bits` | Requested modulus bit length; zero for Gamma1/2. |
| `correct` | One only after verification and equality checks pass. |

Times use a monotonic wall clock, in milliseconds. The harness performs no network communication. Repetitions reuse a public polynomial and HSS setup; each query receives fresh cryptographic randomness. Trial zero is retained, so first-use effects remain visible in raw data. Cleanup of protocol objects is outside each protocol phase, while native evaluation includes cleanup in its inner loop. The harness is suitable for inspecting this prototype's costs, not for claiming a distributed-system latency result.

Public coefficients and inputs are generated by SHA-512 on the ASCII labels `pv-benchmark-v1:coefficient:m:d:index:0` and `pv-benchmark-v1:input:m:d:index:trial`. The digest is interpreted as a little-endian integer and reduced modulo `q`. This makes the workload reproducible without fixing cryptographic randomness. The VAR case replaces the coefficients with the expanded quadratic model.

```sh
python3 scripts/run_experiments.py --profile smoke --trials 3 --output results/measured/local-smoke
python3 scripts/run_experiments.py --profile paper --schemes 1 2 --trials 30 --output results/measured/local-paper-fe-ov
python3 scripts/run_experiments.py --profile paper --schemes 3 --trials 30 --output results/measured/local-paper-hss
```

The paper profile covers the Figure 2–4 parameter grids; it does not generate the historical Pi3 comparison. Dense high-degree HSS runs can be extremely expensive because each nonzero monomial is evaluated with modular exponentiations. The smoke profile is a functional timing sample, not a rerun of the paper's full grid or hardware setup. Use new output directory names; the runner refuses to overwrite previous runs.

The runner stores raw per-trial rows, per-command library/version reports, commands, timestamps, source hashes, revision, and environment information. Source hashes identify the measured code even when a run precedes its eventual commit. Report medians, variation, machine details, and trial counts when making performance claims.

The VAR timing excludes receipt authentication, binding proofs, and application preprocessing. This repository does not implement those components; the historical table claiming complete application costs cannot be regenerated by this benchmark.

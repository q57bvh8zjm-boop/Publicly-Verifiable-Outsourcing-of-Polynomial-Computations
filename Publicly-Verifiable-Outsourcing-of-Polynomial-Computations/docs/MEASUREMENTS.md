# Measurement contract

`benchmarks/benchmark.c` performs actual query generation, all server evaluations, public verification, and reconstruction. It compares the final output with native polynomial evaluation before emitting a CSV row.

| Column | Meaning |
|---|---|
| `scheme` | Canonical name: `Gamma_FE_Sh`, `Gamma_OV_Sh`, or `Gamma_OV_HSS`. |
| `keygen_ms` | Fresh HSS setup once per invocation; repeated in rows for that key. Zero for Gamma_FE_Sh and Gamma_OV_Sh, whose query-specific work is in ProbGen. |
| `native_ms` | Mean of 100 native calls on the same public input; includes the evaluator's allocation and cleanup. |
| `probgen_ms` | Query generation, including fresh masks/encryptions and public verification key. |
| `server_total_ms` | Sum of local server computations executed sequentially on this machine. |
| `verify_ms` | Public verification and preparation of the decoding value. |
| `decode_ms` | Client reconstruction. Very short operations can round to the clock resolution. |
| `client_ms` | `probgen_ms + verify_ms + decode_ms`. |
| `client_ratio` | `client_ms / native_ms`, excluding setup and server work. |
| `input_bytes_per_server` | Canonical fixed-width payload estimate from actual parameters; excludes framing, setup keys, and distribution of the public verification key. |
| `response_bytes_per_server` | 64 bytes for Gamma_FE_Sh, `32*(d+1)` for Gamma_OV_Sh and Gamma_OV_HSS. |
| `paillier_bits` | Requested modulus bit length; zero for Gamma_FE_Sh and Gamma_OV_Sh. |
| `correct` | One only after verification and equality checks pass. |

Times use a monotonic wall clock, in milliseconds. The harness performs no network communication. Repetitions reuse a public polynomial and HSS setup; each query receives fresh cryptographic randomness. Trial zero is retained, so first-use effects remain visible in raw data. Cleanup of protocol objects is outside each protocol phase, while native evaluation includes cleanup in its inner loop. These are local computation timings for the prototype.

Public coefficients and inputs are generated by SHA-512 on the ASCII labels `pv-benchmark-v1:coefficient:m:d:index:0` and `pv-benchmark-v1:input:m:d:index:trial`. The digest is interpreted as a little-endian integer and reduced modulo `q`. This makes the workload reproducible without fixing cryptographic randomness.

```sh
python3 scripts/run_experiments.py --profile smoke --trials 3 --output results/measured/local-smoke
python3 scripts/run_experiments.py --profile paper --schemes Gamma_FE_Sh Gamma_OV_Sh --trials 30 --output results/measured/local-paper-fe-ov
python3 scripts/run_experiments.py --profile paper --schemes Gamma_OV_HSS --trials 30 --output results/measured/local-paper-hss
```

The paper profile covers the Figure 2–4 parameter grids. The historical Pi3 comparison is stored in the reported-data archive. Dense high-degree HSS runs evaluate every nonzero monomial with modular exponentiations, so their runtime grows rapidly with the number of terms. The smoke profile exercises a small parameter set on the current host. Each run writes to a new output directory.

The runner stores raw per-trial rows, per-command library/version reports, commands, timestamps, source hashes, revision, and environment information. Source hashes identify the measured code even when a run precedes its eventual commit. Report medians, variation, machine details, and trial counts when making performance claims.

## Private classification

`applications/private-classification/` evaluates the fixed public quadratic and cubic SVM scores used in Appendix G/Table 7. Run `make classification-check` to generate fresh measurements and validate the results. Set `CLASSIFICATION_OUTPUT` to a fresh path for each run.

These timings use one warm-up query and 12 measured queries per configuration. `client_ms` includes input-to-field conversion, query generation, request serialization, verification, decoding, and cleanup. It starts from quantized features. Training, feature extraction, model loading, transport, and response parsing are outside the measured interval. Servers execute sequentially; `server_sum_ms` is their total work and `server_max_ms` is the largest individual server time.

Payload counts sum all servers' requests or responses, with verification-key bytes recorded separately. The raw CSVs also retain native integer, floating-point, and finite-field evaluation times. The [application README](../applications/private-classification/README.md) documents the model settings, original recorded values, and complete reproduction steps.
